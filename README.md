## 1. Set up Python

Use Python **3.11**. The dependency snapshots were collected from the local `Ratatouille` environment running Python **3.11.14** on Windows. A clean installation and complete rerun with the archived data still need validation.

Open a terminal in the repository root and create an environment:

```bash
python -m venv .venv
```

Activate it with `.\.venv\Scripts\Activate.ps1` in Windows PowerShell, or `source .venv/bin/activate` on Linux/macOS. Then install the analysis dependencies:

```bash
python -m pip install -r requirements.txt
```

Suite2p is used during calcium-imaging analysis because deconvolution is enabled in `kitchen/settings/fluorescence.py`. FFmpeg must be installed separately and available on `PATH` if converting videos. Facemap and the external MEYE workflow are optional pupil-extraction tools, needed only if regenerating those measurements from videos.

The requirements files pin direct dependencies from the local environment; they do not lock all transitive dependencies. Run scripts from the repository root using `python -m ...` so Python can find `kitchen`. There is currently no installable package configuration.

## 2. Download and place the data

See [ingredients/README.md](ingredients/README.md) for the data inventory and supporting files.

The existing `PLACEHOLDER_*` directories mark the destinations. Extract each archive into `ingredients/` so the **actual template names** appear as shown below. Do not leave data inside a directory named `PLACEHOLDER_*`, or add an extra archive-name directory above the template directory.

```text
ingredients/
  PassivePuff_JuxtaCellular_FromJS_202509/
    SST_JUX/
      ... *_datafile.pkl and saved spike-curation files ...
    SST_WC/
    PV_JUX/
    PYR_JUX/
    PYR_WC/                         # used by some analyses
    sst_whole_cell_staining/         # if running whole-cell staining analysis
  PassivePuff_HighFreqImaging/
    HighFreqImaging_Combine_ROIs/
      <mouse_id>/
        <date_FOV_or_ROI_id>/
          ... TIMELINE_*.csv, Fall.mat, INFO_*.xlsx, behavior files ...
    HighFreqImaging_Combine_ROIs_info/
      <mouse_id>/
        ... staining CSVs and *_crop.png previews ...
```

Preserve archive filenames and directory hierarchy: template, cohort, mouse, and FOV identifiers are used by the loaders. The imaging loader currently searches recursively within each FOV directory (`DATA_HODGEPODGE_MODE = True` in `kitchen/settings/loaders.py`).

Paths are derived from the repository location in `kitchen/configs/routing.py`. To keep data or figures on another drive, set `RATATOUILLE_DATA_PATH` or `RATATOUILLE_FIGURE_PATH` **before** starting Python. For example, in PowerShell:

```powershell
$env:RATATOUILLE_DATA_PATH = "D:\recording-data\ingredients"
$env:RATATOUILLE_FIGURE_PATH = "D:\recording-results"
```

On Linux/macOS, use `export RATATOUILLE_DATA_PATH=/path/to/ingredients`. The data path must contain the template directories above.

## 3. Check the installation and load a cohort

Check that the shared analysis loader imports:

```bash
python -c "from kitchen.loader.general_loader_interface import load_dataset; print('Analysis imports OK')"
```

For an initial data check, run this example in a Python console opened at the repository root:

```python
from kitchen.loader.general_loader_interface import load_dataset

dataset = load_dataset(
    template_id="PassivePuff_JuxtaCellular_FromJS_202509",
    cohort_id="SST_JUX",
    recipe="default_ephys",
)
print(dataset)
dataset.status(save_path="cuisine/status_report_SST_JUX.xlsx")
```

Electrophysiology loading uses saved `spike_waveform_curation.pkl` files. If a selection file is missing, the loader opens the Qt waveform-curation interface and requires a saved selection before continuing. Use the archived files to reproduce the paper's selections. Disabling curation or choosing new spikes can change the results.

For calcium imaging, use:

```python
dataset = load_dataset(
    template_id="PassivePuff_HighFreqImaging",
    cohort_id="HighFreqImaging_Combine_ROIs",
    recipe="default_two_photon_mes_parser",
)
print(dataset)
dataset.status(save_path="cuisine/status_report_imaging.xlsx")
```

## 4. Run the analyses

Run commands from the repository root. For example:

```bash
python -m cook.JS_juxtacellular_analysis.script01_WaveformCurator_DatasetOverview
python -m cook.JS_juxtacellular_analysis.script03_SummaryMetric_AvgPSTH_LFP_Waveform
python -m cook.high_freq_imaging.20260206_overview
python -m cook.high_freq_imaging.20260820_further_analysis
```

These research scripts select analyses in their `main()` functions. Several calls are commented out, and some functions terminate early with `exit()`. Running a script executes its current active selection; it does not regenerate every analysis listed in the file. In particular, `script02` currently loads/prints SST sessions with plotting calls commented out, and `script03` currently generates the waveform summary only.
